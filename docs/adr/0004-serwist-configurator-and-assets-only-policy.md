# Serwist configurator mode with an assets-only routing policy

We ship the service worker through Serwist configurator mode (`@serwist/next` config generator plus `SerwistProvider`): the worker source is `src/app/sw.ts`, the `serwist build` step after `next build` emits the build-destination worker to `public/sw.js`, and the app registers it at the served worker URL `/sw.js` under the existing response headers. A pure routing-policy module (`src/sw-policy.ts`) owns the assets-only offline decision — every document navigation, authenticated HTML and RSC payload, session hole, role gate, router prefetch, Server Action, typed-transport call, and versioned REST mount Operation stays network-only with unknown future routes network-only by default. Only public deployment-versioned resources are precached (revisioned static assets, public fonts and icons, the served manifest, the redirect-free marketing page, the static Reference UI, the static Document, and the generic fallback); worker updates wait for tabs to close or reload and never force-reload an active authenticated session.

## Considered Options

- **Classic `withSerwistInit` wrapper (webpack lifecycle)**: the documented shape from the research note (`swSrc`/`swDest`/`swUrl`). Rejected — the integration is webpack-only and this repo builds and develops on Turbopack by default (verified: the default bundler is Turbopack when nothing is configured, and the wrapper only hooks the ignored `webpack` key). Under the repo's pipelines the worker would silently never be emitted, failing the worker-registers acceptance. Switching production builds to `next build --webpack` to feed it would trade away the repo's build direction inside a PWA ticket, so it stays out.
- **`@serwist/turbopack` (experimental route-handler worker)**: Turbopack-native and working. Rejected — experimental status plus an extra native dependency for a fixed-shape problem, and its served URL (`/serwist/sw.js`) does not match the existing `/sw.js` response headers the ticket requires kept.
- **Precaching `/landing` alongside the other public pages**: the plain reading of "public marketing pages". Rejected — the proxy redirects signed-in traffic on `/landing`, so its bytes are not deployment-constant; precaching it would store a signed-in redirect under a public key on installs made while signed in. `/landing` stays network-only live (proxy authoritative) with the generic fallback offline. The exclusion is pinned by the policy unit test.
- **Auto-precaching prerendered routes (`precachePrerendered`)**: less config, offline shells for every page. Rejected — partial-prerender shells of authenticated pages (`/`, `/posts`, `/admin`) are not public resources, and precaching them would violate the public-only inventory and risk serving signed-in chrome offline.

## Consequences

- The `build` script is `next build && serwist build`; the generated `public/sw.js` is gitignored and rebuilt every build. Deployments that bypass `npm run build` ship no worker and get no offline behavior.
- The worker is disabled in development (`SerwistProvider` with `disable` on `NODE_ENV === "development"`), so the Turbopack dev loop stays worker-free with no watch process.
- `SerwistProvider` sets `cacheOnNavigation={false}` and `reloadOnOnline={false}` alongside `skipWaiting: false` / `clientsClaim: false` in the worker — no runtime URL caching, no worker-level TTL, no forced reload of an active session on update or reconnect.
- Data freshness matches pre-PWA behavior by construction: Procedures, REST Operations, roles, permissions, freshness windows, and proxy redirect semantics are untouched; the worker resolves no identity and grants nothing.
- The generic fallback page (`/offline`) is intentionally minimal; issue #44 owns graceful marketing degradation, proxy reachability hardening, and standalone styling on top of it.
- Revisit trigger: if Serwist ships stable Turbopack support in the classic wrapper, or if the audit gate in issue #45 finds the configurator step unreliable, this decision reopens toward the then-supported framework path.
