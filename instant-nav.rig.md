# instant-nav rig: nextjs16-t3-template

- BUILD: local `EXPOSE_TESTING_API=1 npm run build && npm run start` (port 3000). No CI, no Docker, no Vercel preview. Scripts: `build: next build`, `start: next start`, `preview: next build && next start`.
- EXPOSE: `process.env.EXPOSE_TESTING_API === "1"` wired to `experimental.exposeTestingApiInProductionBuild` in `next.config.ts`. Set during `next build` (not only `next start`), never true in real production.
- RUN: `npx playwright test tests/e2e/instant-nav --project=chromium-instant` against `BASE_URL=http://localhost:3000` (prod `next start`). Existing suite uses `testDir: ./tests/e2e`, `baseURL` hardcoded in `playwright.config.ts`; instant tests reuse `storageState` files and must not run against `npm run dev`.
- TEST USER: USER via `tests/e2e/setup/auth.setup.ts` UI sign-up → `tests/e2e/.auth/user.json` (role USER, random `e2e-<ts>@example.com`, fresh/empty posts); ADMIN via `tests/e2e/setup/admin.setup.ts` UI sign-up + direct Prisma promote-before-signin → `tests/e2e/.auth/admin.json` (role ADMIN). No flags/plans/entitlements; locale default; data is per-run random.
- DRIFT: author session vs test user — roles (author may hold ADMIN vs test USER), seeded vs empty post data (new USER sees empty list/zero counts), storageState freshness (random email per setup run), `DATABASE_URL` vs `DATABASE_URL_TEST` (webServer injects test DB; prod rig must do the same), viewport (desktop 1280 vs mobile 390).
- LOOP: local `build → start → test` on one machine; fully agent-drivable, nothing to push, no deploy wait. Stop previous server before starting, fail on `EADDRINUSE`, verify new process owns port 3000 before running tests.
- LIVENESS: n/a for local `build && start` (artifact is freshly built).
- WALLS: `next start` needs test DB (`DATABASE_URL=<test>` from `DATABASE_URL_TEST` via `loadEnv("test")`); port 3000 held by `npm run dev` webServer (`reuseExistingServer: !CI`) — stop dev before prod rig; `SKIP_ENV_VALIDATION`/`NODE_ENV=test` bypasses `src/env.js` validation in tests; Turbopack dev (`--turbo`) vs prod webpack build differ — never trust dev verdicts; prod `next start` does not trust localhost for Auth.js (dev does) — set `AUTH_TRUST_HOST=true` in the webServer env or every `auth()` throws UntrustedHost and pages 500.
